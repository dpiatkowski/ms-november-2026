# Avoid common pitfalls in Azure landing zone deployment

**Speaker(s):** Greg Inks, Joe Ponder, Gokul Raghuraman

## Summary

PwC shares four "scars" from Azure landing zone deployments and a fifth risk coming into view. Tale 1: a strict security baseline blocked apps that were ready to move, so repair by sorting failures into must-fix, exception and observe-first. Tale 2: running out of IP addresses by migrating historical allocation instead of actual need. Tale 3: policy estates need code, lifecycle and governance as an operating model (audit first, deny when ready, exemptions that expire). Tale 4: an incident where everything was green but a ten-minute fix took nine days because ownership across seams was unclear, so a landing zone is a product with one owner.

Tale 5 asks whether an AI agent could operate the landing zone: intent, privilege, traceability, rollback, ownership and guardrails must be in place first, followed by bounded autonomy. Five take-home questions close the session.
