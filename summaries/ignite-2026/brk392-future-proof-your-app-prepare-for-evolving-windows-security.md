# Future-proof your App: Prepare for evolving Windows security standards

**Speaker(s):** Brandon Bray, Mariam Gewida, Michael Draper

## Summary

The session explains Windows baseline protection and how apps can use it. Customers want hardware-backed trust, code integrity, kernel protection and limited privileges; requirements are introduced annually (security processor, secure boot, virtualization-based security, memory integrity, signed drivers, vulnerable driver protection). Apps can respond to a missing baseline, for example by blocking competitive matchmaking, restricting confidential documents, running pre-exam checks or applying conditional access.

The API has two stages: a local readiness audit (query whether baseline protection is active and the next-boot state) which is informational and not tamper-resistant, then cloud-verified attestation where the app's service validates signed device evidence through the Windows Integrity Service. The NTLM reckoning and least-privilege, verified code are also covered, with Adobe as a partner and preview sign-up offered.
